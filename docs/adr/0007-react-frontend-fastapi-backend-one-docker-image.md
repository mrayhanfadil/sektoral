# React frontend, FastAPI backend, one Docker image

The web app was HTML rendered as Python strings by a standard-library HTTP server. It is now a React + TypeScript single-page app (Vite, Tailwind) in `web/`, served with a JSON API by FastAPI (`app/server.py`), and shipped as one Docker image. We chose this so the UI can grow as components with typed API contracts, and so judges and teammates can start the whole app with `docker compose up`. The cost is a Node build step and two toolchains in one repository.

The company update, its PDF and the standalone trace HTML remain documents generated by the Python pipeline; the app links to them rather than re-rendering them. The Audit Trace also has a React view, fed by a whitelisted projection of the trace JSON (`app/trace_view.py`).

## Considered Options

- **Two services (nginx for the React build, a separate Python API)**: rejected; a second container, CORS or proxy configuration, and more to explain in a submission, with no benefit for a single-user local tool.
- **Keep the standard-library server and add JSON endpoints**: fewer dependencies, but a hand-written router and no request validation; FastAPI gives both, plus OpenAPI docs at `/api/docs`.

## Consequences

- The browser receives only whitelisted fields (`app/jobs.py`, `app/trace_view.py`); the raw trace JSON, pipeline exceptions and file paths stay on the server, as before.
- Document routes live under `/files/...` so they never collide with client-side routes such as `/laporan`.
- Brand tokens are defined twice: the Tailwind theme (`web/src/index.css`) for the app and `app/ui.py` for the standalone trace HTML. The PDF renderer keeps its own copy, as before.
